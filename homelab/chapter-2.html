Chapter 02 — First Attack

Kerberoasting to Domain Admin

Operating as an unprivileged domain user, requesting a service ticket for a Kerberoastable account, cracking the RC4 hash offline, then walking into Domain Admin through the recovered credentials.

Attack Path

Foothold as rdingba (low-priv help-desk user) on a domain-joined client. Goal: escalate to Domain Admin without ever touching the DC interactively.

Starting userrdingba
Target SPNsvc_sqlserver
EncryptionRC4-HMAC (etype 23)

Findings

Each finding maps to a specific control that will get applied in Chapter 3.

  • Any authenticated user can request a service ticketThis is Kerberos working as designed — the issue is what gets returned. Because svc_sqlserver supports RC4, the TGS contains a crackable hash.
  • Weak service account passwordPassword123 is in every wordlist on earth. Cracked in under one second on a CPU. Service accounts need 25+ character passwords or, better, gMSA.
  • RC4 encryption still enabledThe DC issued a ticket encrypted with RC4-HMAC. AES-only Kerberos would make the captured ticket significantly harder to crack offline.
  • No detection on the wireEvent ID 4769 was generated but no alerting fires on anomalous service ticket request volume from a single user.
  • Service account is over-privilegedsvc_sqlserver had effective Domain Admin rights through nested group membership — it should have had only the SQL-specific rights it needed.
